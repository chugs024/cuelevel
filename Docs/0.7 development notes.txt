CUELEVEL 0.7.0 (DEVELOPMENT) — REFERENCE-GUIDED CONSERVATIVE MASTERING
10 October 2026. Work in progress; not a release. The signed/notarised 0.6.0 app and DMGs are unchanged.

WHAT CHANGED
1. Reference library in the app (Source/ReferenceLibrary.swift)
   • Import Library… copies library.json and annotations.json into the app's own data folder. Recordings are never copied.
   • Confirmed labels in annotations.json (keyed by SHA-256) take precedence over library.json.
   • References are grouped by content type and summarised as ranges (lowest to highest). Nothing is averaged.
     Reference true peaks are never used as an output ceiling.
2. Reference check, shown under the loudness report for every analysed cue
   • Compares the cue with the references for the selected content type: loudness range, peak-to-average ratio
     (crest), source loudness, and the true peak a fixed gain change to the target would produce.
   • Recommends one of two approaches. It never applies them by itself; "Apply to Settings" does, and only after the
     changes are listed.
     - Preserve: dynamics already sit within the references. Leveler and compression off, range target 20 LU,
       so the output differs from the source by one fixed gain change.
     - Gentle correction: only what falls outside the references is corrected.
         Loudness range more than 1 LU wider than the widest reference → Gentle leveler (Balanced if over 3 LU beyond).
         Audio only is never leveled automatically; a wide music range is flagged as possibly intentional.
         Crest more than 3 dB above the most dynamic reference → peak compression at or below the mode's ratio.
   • Only leveler, compression, range target and working level change. Target, ceiling, output format, content type,
     cleanup (denoise, hum) and tone (rumble, de-ess, harshness, EQ, brightness, declip) stay as the user set them.
   • No Audio + voice references exist yet, so that content type gets a comparison message and no recommendation.
3. Level-independent dynamics (Advanced → "Level-independent dynamics", working level −18 LUFS by default)
   • A fixed gain places the cue at the working level before the leveler, compressor and other level-triggered
     stages; the final loudness pass removes it. Off (nil) for existing settings and presets, so 0.6 chains are unchanged.
   • Recommendations always turn it on.
4. Final-stage transparency
   • The render now records whether loudnorm used one fixed gain ("linear") or fell back to dynamic loudness control,
     for the main output and the WAV copy. Dynamic fallback produces a review note; reports include it.
   • Bug fix: a measured loudness range of exactly 0 LU was passed to loudnorm, which reads 0 as "not supplied" and
     silently switched to dynamic mode. This affects steady material longer than 3 s (tones, very constant loops).
     Now passed as 0.01 LU. Cues shorter than 3 s were not affected.
5. Measurements: sample peak and RMS (astats) are measured with loudness, giving a peak-to-average row in the report.
   Sessions from 0.6 decode unchanged; their analyses show "analyse again" for crest.
6. Reports add finalGainMode and the reference-check lines. The version comes from the app bundle.
7. Builds: Source/build-dev.command builds outputs/CueLevel-dev/CueLevel Dev.app (0.7.0 build 8, bundle id
   local.halllevel.app.dev, data in ~/Library/Application Support/CueLevel Development). It never modifies the
   signed app or the installed app's session. build.command now includes ReferenceLibrary.swift and still
   replaces the signed app; use it only for a release build.

QUICK LEVEL — LOSSLESS DROP WORKFLOW (added 10 October 2026, evening)
Decisions from the user: one fixed output folder; videos delivered as MOV; no limiting (cues without headroom stay quieter
and are flagged); every cue levelled to -18 LUFS. Peak ceiling -1 dBTP (safe for a pure gain change).

How it works
• Inspector → Quick Level switch. First use asks for the output folder (remembered). Turning it on selects
  "Lossless · gain only", -18 LUFS and -1 dBTP.
• Drop files anywhere in the window: each is analysed, levelled and copied to the output folder with no dialogs, using the
  source's base name ("Cue 12.mp4" → "Cue 12.mov"). Existing files are never overwritten ("Cue 12 2.mov"). Files dropped
  while a batch runs are processed when it finishes. Originals are never modified.
• Lossless output (OutputFormat.lossless, AudioEngine.processLossless):
    - Video picture, subtitles, chapters, metadata and timecode are stream-copied (picture packets byte-identical).
    - MP4/MOV/M4V sources become MOV (MP4 cannot carry uncompressed audio); other video containers stay MKV with a note,
      because Resolume may not open MKV.
    - Audio: one exact gain change (FFmpeg volume, double precision). No loudnorm, no resampling, no compression,
      no limiting. Stored as 24-bit PCM (32-bit float if the source is float) at the source's own sample rate.
    - Gain = min(target − source loudness, ceiling − source true peak). If the ceiling is the limit, the cue stays
      quieter by the reported amount.
    - Leveler, compression, cleanup and tone controls are bypassed in this mode.
• Evidence (FFmpeg on Linux, exact command lines): MP4 (mpeg4 + AAC 44.1 kHz + timecode) → MOV: picture MD5 identical,
  timecode kept, pcm_s24le 44.1 kHz, −18.06 LUFS. Peaky cue: gain limited to +2.64 dB, output −24.79 LUFS / −1.00 dBTP,
  flagged. A +6.0206 dB gain on a 24-bit WAV produced exactly 2× every sample; 0 dB is bit-identical.
• Compared with 0.6: 0.6 kept the picture identical too, but re-encoded video soundtracks to AAC 320 kbps and resampled
  everything to 48 kHz; its loudnorm final stage was ~116 dB below a perfect gain change (transparent, not bit-exact).
• Check on the venue system: MOV files carry 24-bit PCM tagged "in24" (standard QuickTime). Confirm Resolume plays a
  levelled MOV and WAV before converting a whole show.
